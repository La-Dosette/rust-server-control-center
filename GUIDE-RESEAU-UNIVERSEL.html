Mettre ton serveur Rust en ligne, quelle que soit ta box.

La méthode ne dépend pas vraiment du pays : il faut une IPv4 publique, une adresse locale stable et une redirection UDP vers le PC. Les menus changent selon l’opérateur ; les règles Rust restent les mêmes.

Guide vérifié le 11 août 2026. Les firmwares de box évoluent : utilise toujours le lien officiel de ton opérateur si un menu a changé.

ÉTAPE 01Diagnostiquer

Control Center → Réseau & ports → Lancer le diagnostic.

ÉTAPE 02Fixer l’IP LAN

Réserve l’adresse IPv4 du PC dans le DHCP de la box.

ÉTAPE 03Rediriger l’UDP

28115 obligatoire, 28117 recommandé, vers le PC serveur.

ÉTAPE 04Lancer Rust

Démarre le profil « amis » et attends la fin du chargement.

ÉTAPE 05Tester dehors

Un ami ou un téléphone en 4G/5G teste la commande F1.

Règle de sécurité : n’ouvre jamais le port RCON TCP 28116 dans la box. Il doit rester limité à 127.0.0.1. N’utilise pas la DMZ et évite l’ouverture automatique UPnP quand une règle précise suffit.

Les règles exactes à créer

Dans Windows

  1. Lance le serveur avec le Control Center.
  2. Le diagnostic doit voir UDP 28115 en écoute sur 0.0.0.0.
  3. Le pare-feu doit autoriser RustDedicated sur UDP 28115.
  4. RCON TCP 28116 doit écouter uniquement sur 127.0.0.1.

Dans la box

  1. Note l’IPv4 LAN affichée dans le diagnostic.
  2. Crée une réservation DHCP pour ce PC.
  3. Ajoute les deux règles UDP vers cette même adresse.
  4. Vérifie que l’IP WAN de la box correspond à l’IP publique affichée.

Si tes amis ne peuvent toujours pas se connecter

1 — Le serveur écoute-t-il vraiment ?

Lance le profil amis, attends « Server startup complete », puis relance le diagnostic. Il doit afficher Port jeu UDP 28115 — OK. Un port UDP ne peut pas être testé correctement quand Rust est arrêté.

2 — L’IP locale a-t-elle changé ?

Compare l’IPv4 LAN du dashboard avec la destination de la règle dans la box. Si elles diffèrent, corrige la règle et crée une réservation DHCP. Une adresse du type 192.168.x.x ou 10.x.x.x est locale, jamais l’adresse à donner aux amis.

3 — CGNAT, DS-Lite ou double NAT ?

Compare l’IP WAN affichée par la box avec l’IP publique du Control Center.

  • Même adresse : la box possède probablement l’IPv4 publique.
  • IP WAN en 10.x, 100.64.x–100.127.x, 172.16–31.x ou 192.168.x : CGNAT ou routeur en amont.
  • Deux routeurs : redirige sur les deux, ou place le premier en bridge/IP passthrough.
  • DS-Lite / IPv6 seulement : demande une IPv4 publique ou Dual Stack.
4 — Fibre, câble, ADSL, 4G/5G ou satellite ?

Fibre/câble/ADSL fournissent souvent une IPv4 exploitable, mais pas toujours. Les accès 4G/5G fixe et satellite utilisent fréquemment le CGNAT. Dans ce cas, une règle locale ne suffit pas : demande une IPv4 publique, une option professionnelle, ou utilise un relais/VPN qui accepte réellement l’UDP entrant. Un tunnel HTTP classique ne transporte pas un serveur Rust.

5 — Le test est-il fait depuis le bon réseau ?

Ne teste pas l’IP publique depuis le même Wi-Fi : certaines box ne prennent pas en charge le NAT loopback. Le test fiable est un client Rust extérieur : un ami, ou un autre PC connecté via partage 4G/5G. Dans Rust, F1 puis client.connect IP_PUBLIQUE:28115. Les sites « port checker » TCP ne prouvent rien pour un port Rust UDP.

6 — Une carte custom doit-elle être téléchargée ?

Une carte custom destinée aux amis doit être accessible par une URL HTTP/HTTPS publique directe. Une URL file://, un chemin Windows ou un lien nécessitant une connexion ne fonctionne que sur le PC hôte.
